## Remaining Risks And Coverage Gaps

1. `npm audit`: 5 vulnerable transitive dependencies (4 high, 1 moderate): tar, brace-expansion, nanoid, postcss, @xmldom/xmldom. Mostly build tooling; severity does not establish an exploitable browser path. Targeted updates and another complete test run are needed.
2. Supabase warns that leaked-password protection is disabled and MFA options are insufficient. No auth settings changed. See [password protection](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection) and [MFA](https://supabase.com/docs/guides/auth/auth-mfa).
3. Supabase flags three authenticated SECURITY DEFINER RPCs (metrics and direct-chat entry points). This is a review warning, not proof of a bypass; caller guards must remain. See [advisor explanation](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable).
4. Recipient labels, email/profile mapping, repeated notification items, and contact/navigation duplication need further work.
5. Admin data-request loading still filters to self; automatic retention is not demonstrated.
6. No fresh signup, invitation consumption, verification email receipt, password reset, or two-device realtime delivery tested end-to-end.
7. No actual Android install/update, background GPS/push, iPhone Safari installation, accessibility screen-reader or physical-device test.
8. No signed release APK build. Existing publishing workflow and rollback behavior still need the separate release audit.
9. No changes deployed. Production still contains failures already fixed in local code.

Do not interpret the green smoke suite as evidence that every feature or every RLS policy has passed an end-to-end test.
